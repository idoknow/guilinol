## 一、核心结论

王城蜜雪冰城项目最终停在整合阶段并被判定为阶段性失败，**直接诱因是王城商厦地块底层地形与建筑体壳存在硬伤，深层根因则是工程流程失控**：在没有先验证城市底层地基、没有先跑通一条最小端到端实景链路的前提下，团队同时铺开 5–6 条业务线并行堆功能，把所有热点文件和跨模块整合压到最后一轮，且阶段验收过度依赖离线单测和局部预览。结果底层地基的一个坑，被上层逐层硬编码补丁放大成难以收敛的“屎山”。

## 三、根因剖析：为什么会变成“屎山”

### 1. 没先验地基和宿主环境，就用业务层硬垫底层缺陷
- 王城商厦北侧（GL04 瓦片 `-768,-256` 与 `-512,-256` 交界处）底层地面本身存在超过 5 米的凹坑，同时宿主 OSM 商厦外壳与周边行道树、盲道 `[39]`、电驴停放点并未提前清理或解耦。
- `web/src/drinks/terrain/plot-sampler.ts:66` 被迫硬写 `WANGCHENG_SIDEWALK_PROFILE` 人行道标高表，用长达数十米的人造台基和 `5.392m` 填高去“盖住”坑洞。
- 底层地基不稳定直接引发连锁雪崩：台基高程一调，`site.ts` 锚点、`shop` 门前台阶、`staff` 招聘牌与工位高度、`npc` 贴地采样、`indoor-view` 进门边界判定、`walkTo` 碰撞落地全部跟着返工，每一层都在为上一层的临时补丁再打补丁。

### 2. 5–6 人大并发各自交付，却始终缺一条从头到尾能跑的端到端主链路
- 并行阶段，几乎每个成员都建了自己的独立夹具、独立 preview 页面和独立单测（`sim/menu.ts` 夹具、`shop/blueprint.ts` 锚点、`staff/anchors.ts` 工位、`npc/preview.ts` 剖面预览、`staff/preview.ts` 员工预览）。
- 在各自隔离的小沙盒里，每个模块都能做到高分（draw calls ≤ 30、10 款饮品特写清晰、12/12 仿真与渲染单测全绿、5 步员工动效顺畅），但**直到最后一轮才拼到真实的 `drinks/index.ts` 里**。
- 一旦放进真实城市主循环，跨模块断层立刻暴露：四组 3D 节点的父子关系与 `refit` 同步没对齐、`drinks/index.ts` 未把 `staff.onDuty` 同步给 `sim.setPlayerStaffMode()`、门洞与室外盲道的局部坐标各模块各写一套。

### 3. 整合启动太晚，共享热点长期冻结导致系统级缺陷攒到尾盘
- `web/src/drinks/index.ts`、`web/src/main.ts`、`web/src/traffic/crowd.ts`、`web/src/walk/view-mode.ts`、`web/src/ui/hotbar.css` 等关键串联点在并行期间全部被划为禁改热点，只能通过 `SHARE+` 排队等整合步统一落盘。
- 这使得很多只需几行就能在早期验证掉的系统问题被活活拖到最后一轮才暴露，例如：
  - `traffic/crowd.ts` 过滤路人后未同步隐藏 `traffic/index.ts` 的 `BatchedMesh` 替身；
  - `main.ts:573` 生产环境仍暴露 `window.viewer.drinks` 调试接口；
  - `drinks-staff-hud` / `drinks-hold-hud` 与宿主 `.hotbar` / `.vehicle-action` 重叠；
  - `drinks/index.ts` 的 `walkInside()` 经宿主 `walkTo` 向下射线落在商厦 2F 屋面/立面而非 1F 地板。
- 整合被压成单点瓶颈，一爆就是跨 4–5 个模块的连环冲突，连续 2 轮无法收敛。

### 4. 验收重单测轻实景，早期用调试捷径掩盖了真实体验失败
- 团队大量验收停留在 `tsc --noEmit`、`node --test` 纯逻辑断言和脱离宿主的局部 preview 截图。
- 即便跑了 DEV 浏览器脚本，早期也大量依赖 `window.viewer.drinks.teleportToShop()` / `walkInside()` / `fastForward()` 绕过真实走路、真实碰撞和真实镜头，导致**“玩家根本无法自然走过 2.8m 门洞在 1F 室内正常看店”**这个致命问题直到后期实景视觉 QA 逐帧审图时才被彻底坐实。

### 5. 缺少硬性的阶段门禁（Stage Gate）与止损机制
- Stage 1 没在 Multica 建前置依赖就直接开工；Stage 2 虽然建了 `IDOK-312`–`IDOK-317`，但**没有把“地基单验收通过”设为下游业务单的硬前置门禁**。
- 当地基和整合已经出现明显失控信号时，各并行线程仍在继续投入高成本细化（冷珠、16 张实拍夜景、5 步手部动效），放大了返工和沉没成本。

## 四、后续大任务必须执行的新规矩（铁律）

从本次复盘起，后续所有大型场景/玩法任务（包括即将评估的小香港项目，以及未来重启蜜雪项目）一律按以下 **6 条硬规矩**执行：

### 规矩 1：地基与宿主体检前置一票否决（Stage 0 硬门槛）
- **怎么做**：任何新场景开工前，必须先开 1 张独立的 **Stage 0「地基与宿主体检单」**。实测目标地块 ≥5 个关键世界坐标的地面高程、OSM 建筑体壳/碰撞体、周边树木/盲道/电驴/路人路径，并产出实景俯视与 45° 截图。
- **验收线**：目标范围地面高差与周边道路连续（异常凹坑/断层 ≤ 0.3m）且出入口无宿主碰撞壳阻挡，才准放行地面直建路线。
- **违背红线**：**严禁在业务层手写高程表或造米级垫高台基掩盖底层地形坏数据**。地基不达标只有两条路：① 阻塞挂靠底层地形修复单，修完再开工；② 架构阶段直接拍板「独立室内场景转场」（如小香港下沉口淡出进独立地下室内），物理隔离城市地基风险。

### 规矩 2：先单人打通最小端到端骨架（Walking Skeleton），跑通实景再并行
- **怎么做**：大任务拆多路并行前，必须先由 1–2 人用灰盒模型打通最小端到端主链路，并冻结共享接口契约（单一父节点、单一坐标换算函数、单一锚点 JSON、单一宿主热点挂载点）。
- **验收线**：在真实世界 DEV 模式下，用真实玩家操作走通「出生 → 走到门口 → 步行穿门自动切第一人称 → 室内环视无黑屏/无穿墙/无吸顶 → 出门恢复视角 → 重复 mount/dispose 零残留」，并附通过视觉 QA 的实景截图。
- **违背红线**：骨架未通过实景验收前，**禁止铺开美术精修、3D 道具细节、NPC 社交气泡、复杂音效等下游并行工作**。

### 规矩 3：Multica 排单强制设前置阻塞与阶段门禁（Stage Gate）
- **怎么做**：开工前先在 Multica 建好父单 + 有序子单，固定三层结构：`Stage 0（地基/宿主体检）` → `Stage 1（端到端灰盒骨架 + 宿主热点接入）` → `Stage 2+（分模块并行填充）`，并在工单间挂显式阻塞依赖。
- **验收线**：每一期子单必须写明可执行的实景验收命令与视觉证据；上一阶段状态未到 `done`（或未由老板拍板豁免），下一阶段子单保持 `backlog/todo`，禁止抢跑。

### 规矩 4：实景端到端视觉验收优先于离线单测，禁止用测试捷径代替玩家路径
- **怎么做**：`tsc` 与 `node --test` 只是提交下限，绝不等于功能完成。每个可交付里程碑必须在真实 DEV 或生产预览中，按真实玩家输入（键盘/触屏步行、真实镜头、真实 HUD 叠层、桌面 1280×720 + 手机竖横屏 390×844 / 844×390）完成端到端走查，并交独立视觉检查逐图给出 PASS/FAIL。
- **验收线**：生产预览自动化验收严禁依赖 `window.viewer.<feature>` 作弊探针或跳过碰撞的瞬移；任何黑屏、镜头卡树、穿墙、HUD 遮挡直接判 FAIL，必须先定位真因（业务层或宿主层）再放行。

### 规矩 5：高频小步整合，宿主热点早冻结、不攒尾盘
- **怎么做**：把宿主热点改动（`main.ts`、`view-mode.ts`、`crowd.ts`、`hotbar.css` 及模块根 `index.ts`）提前到 Stage 1 骨架期一次定型落盘；并行期间每完成一个小里程碑即合流并跑一次真实世界冒烟验证，当天发现的跨模块契约错配当天清零。
- **验收线**：禁止超过 2 轮并行而不做真实世界合流验收；所有 `SHARE+` 热点需求必须标注阻塞级别，P0 级契约缺失（如方块替身穿透、员工状态不同步）必须在下一轮开工前先合入。

### 规矩 6：连续两轮不收敛即刻止损上报，禁止在坏假设上继续堆代码
- **怎么做**：当同一类跨模块整合或底层环境问题连续 2 轮修复仍未收敛时，组长与核心成员必须立即叫停上层业务继续迭代，向上追查底层数据与架构前提，直接向老板给出「修底层 / 换架构 / 暂停封存」的明确拍板选项。

## 五、封存资产与未来重启前置条件（`sim/` & `npc/` 盘点）

虽然本次王城蜜雪项目暂停，但 `web/src/drinks/sim/` 与 `web/src/drinks/npc/` 属于**纯业务逻辑与通用 3D 实例化人群层，零依赖王城地形高程与 OSM 外壳**，本次已随本复盘文档完整封存提交至 `feat/drinks-shop`，未来重启蜜雪或迁移给小香港商铺时可直接复用：

- **已验证可复用能力**（`npx --no-install tsc -p web --noEmit` 退出 0，`node --test web/src/drinks/sim/sim.test.mjs web/src/drinks/npc/npc.test.mjs` 12/12 全过）：
  - 并发顾客硬上限 `<= 8`、门口/柜台排队硬上限 `<= 4` 且超限自动折弯避让门洞；
  - 2.80m 门洞净空走廊与解放东路盲道 `[39]` 禁占约束 + 片区降密配置生成器 `buildDrinksDistrictCrowdThinning()`；
  - 排队顾客全程朝向所属收银台（已在王城世界坐标系 `InstancedMesh` 矩阵级验证通过）；
  - 玩家员工模式 `setPlayerStaffMode(onDuty)` / `PlayerPresenceInput.onDuty`，在岗期间零插队/迎客误报、顾客照常排队下单出杯；
  - 玩家 5 分钟不加入持续出单与远↔近状态无缝接续（DEV 晚高峰实测 35 单、0 死锁、远近往返 `47→55→56` 零重置）。
- **未来若重启蜜雪必须先满足的 4 项硬前置**：
  1. 底层城市地图团队彻底修复王城片区 GL04 地面下陷，使门店区无需 `WANGCHENG_SIDEWALK_PROFILE` 硬编码高程表与 5.39m 人造台基；
  2. 清理或打通王城商厦 OSM 1F 外壳/屋面碰撞体及门前行道树遮挡，保证玩家步行穿门无吸顶、无黑屏；
  3. 同步修复宿主 `web/src/traffic/crowd.ts` 降密区路人未隐藏 `BatchedMesh` 替身的问题，以及 `web/src/ui/hotbar.css` 桌面端底部 HUD 避让；
  4. 恢复 `web/src/drinks/index.ts` 单一父节点坐标系整合与 `sim.setPlayerPresence` / `setPlayerStaffMode` 接线后，再从 Stage 1 实景骨架重新验收启动。

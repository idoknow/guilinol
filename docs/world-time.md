# 全服统一时间（IDOK-502）

游戏内时间（时辰 + 天气）是**全服统一**的：任何两台设备在同一时刻看到的桂林天色、昼夜光照、
路灯与夜景灯箱、建筑亮窗、水面反射完全一致。这份文档写清权威时间从哪来、客户端怎么对齐、
单机与离线怎么兜底、以及改这里会牵动什么。

## 为什么不是"客户端自己走"

改造前 `web/src/ui/sky.ts` 的 `skyClock()` 在每台设备上各自积分时间：进入时刻不同、帧率不同、
切后台挂机不同，两个人同一刻看到的天色就能差出好几个小时；天气还是各自的 `Math.random()` 轮换，
连雾和雨都不会一样。所以问题不是"钟不准"，而是**没有共同的钟**。

## 权威时间源

1. `GET /api/health` 的响应体带 `now`（epoch 毫秒，`functions/api/[[path]].ts`）。这是唯一的
   时间授权，公开、只读，和 `ok` 一样不需要登录。
2. 客户端（`web/src/global-time.ts`）在**首次进入、联机从非 online 跃迁到 online、回到前台、
   以及每 5 分钟**各取一次；用 `rtt/2` 补偿单程延迟，把服务端 epoch 记到 `performance.now()`
   单调时钟上，之后**只靠单调时钟外推**，完全不读系统时钟。
3. 采样不是"最后一次说了算"：保留最近 5 个样本，取**最短 RTT** 那条作锚点；RTT 超过 3 秒的
   弱网样本直接丢弃，不会把之前准确的偏移毒化。两次校时之间还有 15 秒冷却，任何触发源都要过闸。

`/api/health` 没有 `now`（老后端）时**不算校时成功**，继续用本机时钟并在 HUD 标 `全服·本机`，
不会报错也不会卡住加载；连续失败会累加 `worldClock().failures` 且每 60 秒打一条限流日志，
便于区分"全站接口挂了"和"这台机器网络差"。

## 确定性时间映射（`lib/world-time.ts`）

时间不是同步包，而是纯函数：

```
hour    = ((nowMs - EPOCH_MS) mod 24h) / 60s     // 1 游戏小时 = 1 现实分钟
weather = spellWeather(floor((nowMs - EPOCH_MS) / 3h))   // 每 3 游戏小时一段，按绝对时间哈希
```

因为是纯函数，**同一个毫秒在任何客户端都得到同一个结果**，不需要服务端保存任何状态，也不需要
改联机服（`rt` 只同步位姿/战斗/名册，与时间无关）。`EPOCH_MS` 取 `2026-01-01T00:00:00Z`，
不用本地时区。

`weather` 的权重按该时段起始小时走：清晨（4.5–9.5 点）多雾，黄昏（18–21 点）偏阴，其余以晴为
主、偶有阵雨；相邻时段可能连着同一种天气（雾天本来就连着几天），这不影响一致性。

## 客户端表现

- **默认**：`skyClock` 每帧从世界时钟取目标小时，先按 1 小时/分钟推进，再用 0.6 秒时间常数把
  残差吃掉，且**单帧修正量硬上限 25%**（追赶系数用的是 clamp 后的步长）。常态滞后远小于一个
  游戏分钟，肉眼看不出来；切后台很久回来时是平滑扫过去，不会一帧硬切。
- **天气换段**：`blendMs` 拉到 12 秒，`look/time.ts` 的 `evaluate()` 按这个时间常数把雾/雨的
  mix 缓过去，不会闪。手动点「晴/雾/雨」或 `clock.set()` 会把 `blendMs` 复位成 1.2 秒。
- **本地预览**：时辰/天气面板点「晨/午/昏/夜」、拍照模式拨时辰、`clock.set()` 都算本地预览，
  面板标签变成 `本地`，出现「全服」按钮一键交回。拍照模式退出时自动交回全服时间；拍照期间的
  网络重连不会打断预览（重连只在**非拍照**且**非采集锚点**时才把时钟拉回全服）。
- **联机中只读**：`glol:mp-status` 进入 `connecting/online` 后面板降级为只读（按钮置灰），
  景点卡片的「换到此时」同样被拦下，避免有人把自己的天色调得和别人不一样。
- **单人模式**（`IDOK-154`）：面板本来就隐藏，时间照样跟全服走。
- **截图 / 门禁的可复现性**：`?time=`、`?weather=`、`?flow=0` 依旧钉死画面；**裸 `?verify` 保持历史上的
  10:00 固定起点**，否则每张截图都会随当天实际钟点变化，几十个既有脚本就不可复现了。
  需要在 `?verify` 链接上验全服时钟时加 `?worldtime=1`（`verify-world-time.mjs` 就是这么做的）。
  纯 `?verify` 直链也不会去打 `/api/health`，不给截图门禁增加网络往返。

## 兜底与可观测

| 情况 | 行为 | `worldClock().source` |
| --- | --- | --- |
| 正常联机 | 对齐服务端时钟 | `server` |
| 单机 / 首次访问 / 接口失败 | 用本机时钟走同一套映射（同机单人联机一致） | `local` |
| 设备时钟被改 | 单调时钟外推，天色不受影响 | `server` |

`window.viewer.worldClock()` 返回 `{now, source, failures, local, linked, anchored, hour, weather,
targetHour, targetWeather, remainingMs}`：`hour` 是这台设备此刻**渲染**的小时，`targetHour` 是全服
权威小时，`now` 是客户端估算的服务端 epoch（验收脚本拿它跟**测试进程侧真值**比对，而不是自比自）。

### 联机状态为什么不能每次都校时

`web/src/net.ts` 每收到一条在线人数广播都会派发 `glol:mp-status`（`state:'online'`）。如果监听器
见到 `online` 就校时，全服任意一人上下线都会让所有在线客户端一起打 `/api/health`（惊群）。所以
监听器只在**前态不是 online、新态是 online** 的跃迁上触发，另外还有 15 秒冷却闸兜底。

## 改这里会牵动什么

- `GAME_HOUR_MS` 改成 1 游戏小时 = 1 现实小时，会让一轮昼夜变 24 小时；所有夜景/黄昏截图脚本
  的 `?time=` 锚点仍然有效（pin 覆盖全服时钟），但玩家观感会变，属于产品决定。
- `WEATHER_SPELL_MS` 变了，天气换段频率跟着变，`verify-world-time.mjs` 的分布断言要同步。
- 新增依赖时间的效果时，请只读 `env` / `atmo`（`look/time.ts` 的 `evaluate()` 输出），不要自己
  再积分一份小时，否则会重新引入"两个人天色不一样"。
- 截图与门禁脚本用 `?time=`、`?flow=0`、`?weather=` 固定画面，这些参数**永远压过**全服时钟。

## 验收

```sh
node --import tsx --test scripts/test-world-time.mjs   # 纯函数：同刻一致、跨日连续、天气分档
npm run build && node scripts/verify-world-time.mjs    # 两台无头客户端，其中一台本机时钟偏 37 分钟
```

`verify-world-time.mjs` 的权威基准是**测试进程侧的真值**：`/api/health` 被拦成返回
`真实时刻 + 10 分钟服务端偏移`，所以"服务端几点"完全由测试侧给出，客户端无法自证。
覆盖：两台同刻一致（其中一台本机时钟偏 37 分钟，若不校时会偏离 37 分钟而不是几十毫秒）、
`night` 光照因子一致、联机状态重复上报不惊群（6 次 `online` 上报应触发 0 次额外请求）、
offline→online 会重新校时、拍照本地预览期间的重连不打断预览且退出交回全服、
裸 `?verify` 零请求（即使 `localStorage['glol.mp']='1'`）且仍是固定 10:00 晴天、
深链 `?mode=walk` 也会校时、接口 503 时的离线兜底。

# Rock 实拍照片的拍摄位置和朝向

Rock 2026-11-19：照片都带定位，可以用来确定拍摄地点，再推断建筑的位置。

`photo-locations.json` 记录了每张照片（键名是相对 `docs/refs/rock/` 的路径）的拍摄信息，是从原图 EXIF 里提取的。入库的 JPG 本身仍然去掉了 EXIF，只在这个 JSON 里保留位置信息，这是 Rock 同意的。

| 字段 | 含义 |
|---|---|
| `lat` / `lon` | 拍摄点，WGS84（iPhone GPS 原始坐标，与 OSM 一致，不是 GCJ-02） |
| `x` / `z` | 换算成游戏世界坐标（米），原点 25.280N 110.300E，x 向东、z 向南，与 `pipeline/common.py` 的 `ll2xz` 一致 |
| `alt` | GPS 海拔（米），误差较大，只作参考；镜头高度按地面加约 1.5 m |
| `heading` | 镜头朝向，正北为 0°，顺时针（`headingRef: T` 表示真北） |
| `hAccuracy` | 水平定位误差（米）。中位数约 4.7 m，最大约 36 m；误差大的照片要结合画面内容校正 |
| `focal35` | 35 mm 等效焦距；水平视场角 = 2·atan(36 / (2·focal35)) |
| `support` | 人工标注的拍摄支撑面。复核指出的 6 张桥上照片标为 `deck`。若原点落在水上，允许在 `hAccuracy` 圈内借最近桥面的高度；保持原始 x/z，并在索引标记采样距离。 |
| `time` | 拍摄时间（本地时间） |

## 怎么用
1. **定位建筑**：在俯视图上把拍摄点和朝向画成扇形（视场角按 `focal35` 算），照片里看到的建筑必然落在扇形里。多张照片从不同角度看同一栋楼，扇形的交集就是它的位置。这样可以校正 OSM 或 Overture 轮廓的偏移，以及楼与楼的相对关系。
2. **同机位对比**：游戏相机放在 `(x, 地面高度 + 1.5, z)`，水平朝向取 `heading`（游戏里 z 向南，所以 yaw 要换算），视场角取上面公式的结果，再截图和照片左右拼图。已实现为 `npm run photo-match`（见 README「实拍同机位与完整回归」；高度取步行支撑面，`support` 字段见上表）。
3. **路线**：按 `time` 排序，就是 Rock 的行走路线，可以叠加在俯视图上检查路网。

## 注意
- 树下、楼边的 GPS 会偏，偏差在 `hAccuracy` 里能看出来。几张照片的位置互相矛盾时，以画面内容（路口、牌坊、门洞等明显特征）为准。
- 走廊或门洞里面拍的照片，GPS 可能跳到楼的另一侧。

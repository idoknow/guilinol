# GL01 分块格式

静态入口 `world/manifest.json`，version = 1。`bbox` 为请求的南、西、北、东 WGS84 度数；`origin` 为纬经度。沿用 `pipeline/common.py`：原点 (25.280, 110.300)，x 东、z 南，y 为 DEM 绝对高程，米。`extent` 是向外对齐到 256 m 的 `[minX,minZ,width,depth]`；块列表按 z、x 递增，条目含左上角世界坐标 `x,z`、相对 manifest 的 `file`、落盘 `bytes`。

`overview.heights` 是小端 int16 分米显示高程（湿点为水面），网格间隔 `overview.step` = 32 m；从西北到东南逐行，每行 `width/32+1` 个值，共 `depth/32+1` 行。`overview.texture` 为整图 PNG，北朝上。两者不在块内。

每块一个 `.glc`，磁盘内容是一个 gzip 流（静态服务不要额外标记 `Content-Encoding: gzip` 来解开内部流）。解压后各段紧邻、没有对齐填充，所有多字节数值小端：

|顺序|类型 / 长度|含义|
|---|---|---|
|1|4 字节 ASCII `GL01`|格式标识|
|2|4 × uint32|依次是建筑顶点数 V、索引数 I、碰撞 JSON 字节数 C、PNG 字节数 P|
|3|65×65 int16|4 m 间距裸地，绝对高程分米；水下至少比水面低 2 m|
|4|65×65 int16|水面绝对高程分米，`-32768` 表示干地；同一连通多边形取 DEM 中位数（重叠处后绘制者优先）|
|5|V × 3 int16|建筑 x,y,z；x/z 为相对块左上角的厘米，y 是绝对高程分米|
|6|V × 3 int8|建筑法线 x,y,z，分量除以 127|
|7|I × uint32|三角面索引；可能未对齐，JS 用拷贝或 DataView 读取|
|8|C 字节 UTF-8|碰撞轮廓 JSON 数组：每项 `[基底分米,屋顶分米,[外环,洞环…]]`。环是 `[[x厘米,z厘米],…]`，局部坐标、不重复闭合点|
|9|P 字节|256×256 RGB PNG，北朝上，1 m/像素，地面、绿地、水面、道路已烘焙|

网格两维均包含端点，共享边上的两块取自同一全图网格。建筑按块裁切，同一栋楼跨块共用基底和层数；每块合为一个 mesh。基底按代表点 DEM 采样，墙向下延伸 3 m 防小坡露缝，碰撞数据不含该延伸。

查看器用 8 m 间距抽样近景，湿点使用水面而非河床；边缘高度插值到 32 m 总览边，防止不同 LOD 裂开。细块加载完成才将相应总览三角形退化，卸载时恢复，同步切换，不依赖深度偏移。碰撞段为后续步行保留，飞行不解析。
